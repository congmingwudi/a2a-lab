# A requirements corpus → evidence-graded audit → hardening across the stack

**Feature area:** multimodal input (slide images as the corpus), large-scale
code investigation with evidence discipline, plan-then-implement across code,
cloud runtimes, and a production Salesforce org.

## The story

A trusted source — a colleague's internal "Headless 360 Anti-Patterns &
Remediation Tips" deck — arrived as **two slide screenshots** (5 categories,
34 anti-pattern bullets covering security, secrets, OAuth, PII, agent design,
and guardrails). Instead of treating it as a checklist to nod along to, the
slides were dropped into `tmp-docs/` and Claude was asked to **analyze the
whole corpus through the lens of the lab**: does each claim hold, and does the
lab commit it?

The result is `tmp-docs/antipattern-analysis.md` — a working document built
from **two code audits with `file:line` evidence** (security/auth/trace, and
Apex/MCP/guardrails), cross-referenced against `config/insights.yaml`,
`plan/02-matrix.md`, and ADRs D7–D34.

## What made the analysis honest instead of performative

Every one of the 34 claims got **two independent gradings**:

- **Is the claim true?** ✅ valid · 🟡 valid-with-nuance · ❌ falsified as
  stated (with cross-platform evidence) · ⚪ N/A to the lab.
- **Does the lab commit it?** `avoids` · `commits-deliberately` ·
  `commits-debt` · `partial` · `n/a`.

That second axis is the interesting one. A compliance-checkbox pass would mark
every violation as a defect; the evidence-graded pass distinguished **debt**
(e.g. plaintext secrets in Lambda env vars — S4) from **deliberate
instrumentation** (e.g. synchronous long-running cells — G5 — which *are* the
experiment that produced the measured timeout-budget-stack numbers). And the
lens ran both directions: some source claims were **falsified with the lab's
own measurements** (S1's "use the hosted MCP server" fails when exactly one
native protocol endpoint exists across five platforms). The audit pushed back
on the trusted source where the evidence demanded it — and confirmed its
flagship claims where it could (G1 runaway loops, with the lab's D27
delegation guard as a working reference implementation).

## Requirements → typed, tracked work

The scorecard was then converted into four artifact streams, each with stable
IDs so later sessions can work from them:

- **Fix backlog F1–F8** — the validly-flagged debts, each with location and
  acceptance criteria: secrets → Secrets Manager on the AgentCore runtimes and
  shim Lambda (F1), a credential scrub pass in the trace/observability sinks
  (F2 — redact `Bearer`/`access_token`/`client_secret` patterns while keeping
  the raw-payload-evidence ethos for content), OAuth scope diet on the
  External Client App (F3), MCP output schema + contract version (F4),
  hardcoded Agent Engine path → Custom Metadata (F5), per-twin client apps for
  per-caller identity (F6), a versioned rider grammar (F7 — turning "regex
  scraping" into "parsing a versioned text contract"), and an Apex batch guard
  (F8).
- **Candidate insights** (I-A2A-1…4) — new findings *generated by* the lens,
  drafted for `config/insights.yaml` in its honest status legend.
- **Experiment proposals E1–E6** — where a claim was testable but untested,
  the remedy is a runnable lab cell (e.g. a Trust Layer wire test, an
  `input-required` handoff cell), not an opinion.
- **Lab-guide hooks** — sections the corpus demanded in the (since-built, D35)
  Lab Guide: the rider grammar spec, the security posture, and a documented
  list of *known deliberate anti-patterns*.

The fixes span the entire stack — Python trace layer, Lambda deploy scripts,
AgentCore runtimes, Salesforce org config, and Apex classes (production-org
deploys, so ≥75% test coverage gates apply) — and the plan sequences them
against real milestones (F1 lands before the hosted public-demo cutover).

## Session continuity

`tmp-docs/` is scratch space, not `plan/` — so a **memory entry** records the
doc's role and the agreed sequencing, with the instruction "work from its
F*/E*/I-A2A-* IDs". Any later session that touches fixes, insights, the
readout deck, or the lab guide starts by re-reading the working doc, not by
re-deriving the analysis.

## Teaching points for the deck

- **Slides are a valid corpus.** Claude read the anti-pattern deck straight
  from screenshots — no transcription step — and turned prose bullets into 34
  atomic, checkable claims.
- **Investigate against reality, not vibes.** Every verdict carries
  `file:line` evidence or a measured number; claims the codebase couldn't
  confirm became *experiments*, not assertions.
- **Two-axis grading beats checkbox compliance.** "Is it true?" and "do we do
  it?" are different questions, and "we do it *on purpose, instrumented*" is a
  legitimate third answer for a lab.
- **Requirements become IDs.** F1–F8 / E1–E6 / I-A2A-1…4 give the human, the
  model, and future sessions a shared vocabulary — the same discipline as the
  ADR log, applied to externally-sourced requirements.
- **Hardening as a story arc:** trusted-source corpus → evidence audit →
  prioritized plan → fixes applied across code, cloud, and org — then
  showcased in the readout deck as "practiced, not just preached."
