## What changed, by item

### A4/F07 — idempotent, retryable brief delivery

The watcher's record of serviced sessions was an id-only set and a session was
marked serviced *unconditionally* — a failed Salesforce write was never retried
and there was no terminal-failure state. Three layers changed:

- **Delivery ledger (`src/briefs/__main__.py`).** The `serviced_sessions` list
  becomes a per-session outcome ledger `{session_id: {status, attempts, at,
  calls, last_error}}` where `calls` is keyed by tool_use_id. `_session_status`
  is the decision: `delivered` only when every save call is `ok` and there is no
  error; `failed` (terminal) once `attempts >= MAX_ATTEMPTS`
  (`A2ALAB_BRIEF_MAX_ATTEMPTS`, default 3); `pending` otherwise — a zero-save
  session is `pending`, never silently `delivered`. `_ledger_from_payload`
  migrates the legacy list to `delivered` entries with an ascending ordinal so
  eviction stays deterministic and legacy entries (no `at`) rank below
  timestamped ones. The ledger is store-first (hosted Aurora via `_state_store`)
  with the `.a2alab/` file as laptop fallback, bounded to `LEDGER_CAP` (500),
  and a failed *write* is raised, not swallowed — a lost write re-delivers.
- **Save gated on the ledger (`src/briefs/runner.py`).** The `save_brief` custom
  tool now consults `prior_calls`: a tool_use already recorded `ok` is surfaced,
  not re-written; a new/failed one is (re)attempted, its outcome (`ok`/`failed`
  with error text) appended to `calls`, and the session is still answered. The
  runner returns `calls` as a list; the watcher is the seam that keys it by
  tool_use_id.
- **Salesforce idempotency (`src/briefs/salesforce.py` + metadata).** Delivery
  upserts `A2ALab_Account_Brief__c` and its follow-up `Task` on a composite
  external-id `A2ALab_Delivery_Key__c = f"{research_session_id}#{account_id}"`
  via `PATCH /sobjects/{sobject}/{ext_field}/{key}` — atomic, so a concurrent
  losing writer matches the winner's row instead of creating a duplicate. New
  field metadata (text 255, `externalId`, `unique`, `caseSensitive=false`) on
  both objects, plus FLS in `A2ALab_Agent_Actions`.
- **Console reader (`src/console/app.py`) + UI surface.** Operator-only
  `GET /api/briefs/outcomes` reads the same ledger (store-first, file fallback)
  and returns `{sessions, summary}` sorted failed-first. It distinguishes three
  states rather than collapsing them to `0/0/0`: an **empty ledger** (`note` —
  "the watcher has not serviced a scheduled session"), a configured-store
  **outage** (`error` — "Aurora … did not respond … an outage, not an empty
  ledger"), and populated. The console now *renders* it: a **Scheduled Brief
  Delivery** section under Infrastructure (`index.html`, `view.type === "briefs"`)
  — operator-only (hides itself on 403, restores on sign-in), a D57 canvas with a
  `Delivery | Details` tabbar, failed-first status pills, and a Details pane
  citing D81 so the D-chips linkify. Added to `SIGNED_IN_LOADERS` and
  `MON_SECTION_LABELS`. (Round 1: Codex found the route had no UI surface; this
  is it.)

### A5/F03 (write half) — deterministic account resolution

`save_brief` no longer hands a model-chosen `LIKE '%name%'` to a production
write. `_resolve_account` (`src/briefs/salesforce.py`): reject empty; if the
name hits `A2ALAB_BRIEF_ACCOUNT_MAP` (trusted JSON env), resolve to the mapped
Id with a binding check that **rejects a name/Id mismatch**; else exact
`WHERE Name = LIMIT 2` (>1 → ambiguous, candidates listed), else a single
escaped `LIKE` (`_soql_like` escapes `\ ' % _`). Ambiguity and emptiness raise
with the candidates named rather than writing to a guessed row.

### A11/F02 — shim session isolation by verified caller

The pinned a2a-sdk generates a context id for every inbound message, so the old
`req.session_id is None` guard was dead and one `shim-shared-{platform}` session
served *all* callers. Fix threads the identity the auth layer actually verified:

- `src/interop/servers/auth.py` publishes the verified JWT `sub` in a
  `contextvars.ContextVar` (`VERIFIED_SUBJECT`), set/reset around the downstream
  call — request-bound, so concurrent requests can't cross.
- `src/interop/servers/a2a.py` reads it in `AdapterExecutor.execute` and stamps
  `metadata["verified_subject"]`, **overwriting or dropping** any caller-asserted
  value (a body field can't steal another user's session).
- `src/platforms/agentforce/proxy.py` keys the reused session on
  `(platform, verified subject)`, falling back to the platform-only key only for
  the legacy service token (no verified subject).
- `src/platforms/agentforce/client.py` adds a per-`lab_session_id`
  `asyncio.Lock` (double-checked) in `ensure_session`, so two racing asks on one
  key create exactly one Agentforce session, not one each.

The concurrency guarantee is tested end-to-end: `test_shim_session_isolation.py`
drives the real `TokenAuthMiddleware` → real `AdapterExecutor` → real proxy with
two subjects forced simultaneously in-flight (an `asyncio.Barrier`), asserting
each keys by its own subject.

## Deploy runbook (work machine)

Every affected image bakes `src/`, so each is a **full rebuild** — `--skip-build`
would ship the old code. Order: schema first (the writer's idempotency depends
on the unique fields existing), then the code images.

1. **Salesforce Metadata API — deploy the field FIRST, then scan.** The earlier
   draft (and D81 as written) had this backwards: it scanned
   `A2ALab_Delivery_Key__c` for duplicates *before* deploying it, which is an
   impossible ordering — a SOQL `SELECT` on a field that does not yet exist
   errors with `No such column`, so the gate can never run. The executable order
   inverts it, and is safe because **a unique external-id field ignores NULLs**:
   deploying it to a populated object succeeds as long as every existing row's
   value is null, which it is (the column is brand new).
   1. Deploy the two `A2ALab_Delivery_Key__c.field-meta.xml` files (text 255,
      `externalId`, `unique`, `caseSensitive=false`) + the `A2ALab_Agent_Actions`
      permset FLS via the Salesforce DX MCP `deploy_metadata` (Apex-free, no test
      run needed for field+permset). Every existing row is null on the new field,
      so the unique constraint is satisfied on arrival.
   2. **Now** the field is queryable — scan for the (impossible-by-construction
      but cheap-to-verify) case of a pre-existing duplicate before the writer runs:
      ```sql
      SELECT A2ALab_Delivery_Key__c, COUNT(Id)
      FROM A2ALab_Account_Brief__c
      WHERE A2ALab_Delivery_Key__c != null
      GROUP BY A2ALab_Delivery_Key__c HAVING COUNT(Id) > 1
      ```
      (and the same on `Task`). Both are guaranteed empty immediately after step
      1.1 (all-null), so this is a post-deploy assertion, not a pre-deploy gate.
   3. Backfill is **optional and only matters if a *pre-existing* brief is
      re-delivered**: the writer keys new rows by `<session>#<account>`, which is
      unique per run, so it never collides with a null legacy row. Skip unless you
      intend to re-run an old session against an already-delivered account.

   **D81 amendment (operator-owned).** The ADR text repeats the impossible
   scan-then-deploy ordering; `settle` is an operator verb, so I am not editing
   the ADR here. Proposed wording for the operator to fold into D81: *"The unique
   `A2ALab_Delivery_Key__c` field is deployed FIRST (safe on the populated object
   because unique external-id fields ignore NULLs and every existing row is
   null); the duplicate scan is a post-deploy assertion, not a pre-deploy gate,
   since the field is not queryable until it exists."*
2. **Hosted watcher/runner (WS14):** `deploy/briefs/deploy_briefs.sh` — carries
   A4 ledger/retry + A5 resolver. New env `A2ALAB_BRIEF_ACCOUNT_MAP` /
   `A2ALAB_BRIEF_MAX_ATTEMPTS` are in the script's allow-list; set them in the
   task's secret if used (both optional — unset = resolve-by-name, 3 attempts).
3. **Faces:** `deploy/faces/deploy_faces.sh` — verified-subject threading in
   `a2a.py`/`auth.py`.
4. **Shim:** `deploy/shim/build_zip.sh && deploy/shim/deploy_shim.sh` — proxy
   reuse key + client per-key lock.
5. **Console:** `deploy/console/deploy_console.sh` — the A4 `/api/briefs/outcomes`
   reader only.
6. **Bridge: no b3 change** — not redeployed.

**Hosted smoke** (memory `hosted-smoke-via-alb-host-header`): two verified
subjects isolate at the shim (distinct Agentforce sessions); a failed brief is
retried on the next tick then goes terminal `failed` at the cap; a re-delivered
session is a no-op (one brief, one Task on the composite key).
