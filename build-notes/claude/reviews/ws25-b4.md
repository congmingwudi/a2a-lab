### Deviations from the rev-2 text (none weakens a test)

1. **New autouse fixture `_no_twin_routing` (test hermeticity — a genuine scoped
   issue found while writing E1/E2).** Twin routing runs *before* the session
   cache (`proxy.py` `handle()`: `TWIN_ENV_BY_PLATFORM` lookup, then a separate
   `AgentforceClient` per twin), and each client caches its own sessions. E1/E2
   use `platform="foundry"`, which maps to `SF_FOUNDRY_AGENT_ID`. In a shell
   that has sourced `.env`, that variable is set. Alice's request then goes to a
   freshly built **real** `AgentforceClient.from_env()` twin instead of the
   recording client. Demonstrated: with `SF_FOUNDRY_AGENT_ID=0XxFOUNDRY`
   exported, E1/E2 failed with `ValueError: not enough values to unpack
   (expected 2, got 1)`. With a full `.env` that client would have attempted
   real Salesforce calls. The fixture `delenv`s every `TWIN_ENV_BY_PLATFORM`
   value, which pins the file to the single-client topology where the collision
   is live. After the fixture:
   - with all four twin variables exported: **26 passed**;
   - the red set against the b3 proxy is **identical** to the pre-fixture red
     run (diffed);
   - the mutation results are unchanged (all six re-run).
2. **E1/E2 also assert the exact keys after the inequality**
   (`shim:sub:alice:value:foundry`, `shim:shared:value:foundry-alice`). Without
   this, a broken JWT chain would leave *both* callers unverified. Their keys
   (`shim:shared:value:foundry` vs `…foundry-alice`) would still differ, and E1
   would pass vacuously. These literals contain no reserved characters, so no
   mutant changes them (E1/E2 stay green under all six, as the plan expects).
3. **H4 also asserts 441 distinct keys.** This is redundant given the left
   inverse, but it states the injectivity conclusion directly.
4. **The helper is read through `proxy_mod` at call time** (a two-line wrapper
   in the test file), not imported by name. Before the fix the file therefore
   still collected, and the E-tests' collision reds were visible rather than
   masked by one `ImportError`.
5. **E2's riders are built with `delegation.delegate()`**, the real D27 rider
   grammar, not a hand-written string. `platform_of` then parses them through
   its own `caller-platform:` regex.
6. **The call site keeps `subject` as a local variable** (two lines, not the
   plan's one-liner), because the one-liner is 102 characters at that
   indentation (ruff line length 100). The semantics are the same.

## Known limits

- **Residual by design (D81/D119).** Shared-token callers still share one
  Agentforce session per *exact* platform string among themselves. b4 closes
  the forge *into a verified caller's* session, and nothing more. Refusing the
  shared-token credential at the shim is the separate, operator-owned action,
  and it waits on moving Foundry's `x-lab-token` connection
  (`deploy/foundry/provision_foundry.py#L103`) to another credential.
- **The platform is not whitelisted.** That is out of scope per the plan,
  because it would be a contract change across every D27 seam.
- **How exploitable b3 was depends on twin routing (new observation).** The b3
  collision shares a *session* only when both platform values resolve to the
  same `AgentforceClient`. That is always true for unmapped platforms. It is
  also true for `claude`, whose twin variable `SF_AGENT_ID` *is* the default
  client's agent id, so no override happens. For `foundry` it holds only while
  `SF_FOUNDRY_AGENT_ID` is unset on the shim. The defect was therefore live on
  the hosted shim whatever the Foundry twin setting was (for example
  `claude` / `claude-<subject>`), and the smoke below uses an unmapped platform
  so the result does not depend on twin env. The fix does not depend on twin
  routing at all.
- **Subject typing.** The call site relies on `verified_subject` being `str`
  or absent. The executor stamps only a truthy JWT `sub`, and PyJWT ≥ 2.10
  rejects a non-string `sub` (`InvalidSubjectError` is a `PyJWTError`, so
  `identity.verify_token` returns `None`). The lockfile pins 2.13.0. The shim
  bundle's range is `pyjwt[crypto]>=2.8,<3` and resolves to the latest. Even on
  a PyJWT < 2.10, a non-string `sub` would make `quote()` raise, so the request
  fails closed rather than sharing a session. Such a token also needs the lab's
  RS256 private key, because the lab issuer always sets `sub` to the username
  string. An empty-string subject (unreachable: the executor drops falsy
  subjects) gets its own `shim:sub::…` key, which also fails closed.
- **Evidence scope.** These are unit and loopback tests through the real
  middleware, executor and proxy, with the Agentforce client faked. Live shim
  behaviour is unproven until the operator smoke below. The left inverse is
  *checked* over 441 tuples and *argued* for the rest by the four-shape split
  (`_enc` output never contains `:`). The mutation set is the plan's six, not
  an exhaustive campaign.
- **Cache keys change once.** Every warm shim cache key changes on deploy, so
  each in-flight shim conversation starts one fresh Agentforce session. The
  cache is per Lambda instance and in memory, and nothing persists the old keys.

**2. Smoke: isolation, the forge, and a positive control.** Use two directory
users whose JWTs the shim verifies (b3 used `ryan` and `ana`). The platform `P`
(`ws25b4-smoke-<hex>`) is deliberately **unmapped**, so the verified platform `P` and the forged

session, so a "no recall" here is real evidence (see Known limits).

```sh
cd ~/projects/claude-code/rc-a2a
set -a; source .env; set +a
PYTHONPATH=src uv run python - ryan ana <<'PY'
import asyncio, os, secrets, sys, uuid
from interop import identity
from interop.clients.a2a import A2AClient
from interop.models import AgentRequest

URL = os.environ["AF_SHIM_A2A_URL"]
USER_A, USER_B = sys.argv[1], sys.argv[2]
P = "ws25b4-smoke-" + secrets.token_hex(2)   # unmapped -> default twin; fresh per run
WORD = "kestrel-" + secrets.token_hex(3)

def client(cred):
    return A2AClient(URL, auth={"header_name": "x-lab-token", "header_value": cred},
                     target_name="agentforce-a2a-shim", source_name="ws25-b4-smoke",
                     timeout=35)

async def ask(cred, platform, text):
    tid = uuid.uuid4().hex
    meta = {"delegation": {"caller": "ws25-b4-smoke", "platform": platform, "depth": 1}}
    resp = await client(cred).ask(AgentRequest(message=text, trace_id=tid, metadata=meta))
    return tid, resp.text

async def main():
    a, b = identity.issue_token(USER_A), identity.issue_token(USER_B)
    shared = os.environ["A2ALAB_TOKEN"]
    recall = "What code word did I give you earlier in this conversation? If none, say NONE."
    steps = [
        ("1 A plants word", a, P, f"Remember this code word for later: {WORD}. Reply only OK."),
        ("2 A recalls (positive control)", a, P, recall),
        ("3 B recalls (two JWTs, two sessions)", b, P, recall),
        ("4 shared-token forge as P-A", shared, f"{P}-{USER_A}", recall),
    ]
    for label, cred, platform, text in steps:
        tid, answer = await ask(cred, platform, text)
        print(f"{label}\n  trace_id={tid}\n  word_in_answer={WORD in answer}\n  answer={answer[:160]!r}")

asyncio.run(main())
PY
```
