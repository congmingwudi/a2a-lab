## Round 2 — response to Codex's verdict (2026-09-06, commit after 1ddb696)

Codex's verdict (`build-notes/codex/codebase-review/reviews/ws25-b1.md`) was
REQUEST CHANGES. Every finding was verified against source before it was
answered; all three A1 leaks and the bundle cold-start reproduced here.

| Finding | Answer | What changed |
|---|---|---|
| A1 regex unsafe for valid JSON (unicode-escaped key, array value, object value, nested escaped quote) | **fixed** | `redact()` is now parse-first: a string that parses as a JSON object/array is redacted STRUCTURALLY and re-serialized only if something was scrubbed (secret-free bodies stay byte-identical); the regex is the fallback for bodies that do not parse (clipped, malformed), and it no longer matches bracketed values, so it cannot corrupt a body it does not scrub. All four probe shapes pass; six new tests cover them plus byte-identity and a clip-boundary split. |
| A3 obs MCP bundle does not cold-start (`interop.secret_env` not copied) | **fixed** | `build_zips.sh` copies `secret_env.py`; `obs_mcp.lambda_entry` loads the runtime secret first; a test parses the script's copy list against every `from interop.X import` in `mcp_http`, `obs_mcp`, `observability/pg.py` and `store.py`, so the next module cannot go missing the same way. |
| A3 coverage overstated (faces/console guard ARN only; shim only loads; `A2ALAB_MODE=hosted` and the opt-out untested there) | **fixed** | `is_hosted()` now also reads `AWS_LAMBDA_FUNCTION_NAME` and `ECS_CONTAINER_METADATA_URI_V4` (the runtimes themselves — the obs Lambda has no ARN); faces, console and the shim call the shared `require_token`; tests cover every signal and the opt-in for faces and console. The shim's guard is exercised only by import on a runtime with `mangum` (not installed here) — noted, not claimed. |
| A2 decision 1 — enforce after the parser, or buffer exactly once | **adopted** | One policy function (`interop/authz.py`); REST calls it in the handler; MCP/A2A call it from the WireTap, which already buffers the body exactly once — no second read anywhere. A denial is answered through the tap so it is recorded as a 403 error hop. Tests cover `/invoke`, `/invocations`, `tools/call`, v1 `SendMessage`, 0.3 `message/send`, and the reads that stay open. |
| A2 decision 2 — `machine` only on gateway routes | **adopted with evidence** | The Agent Fabric gateway fronts EVERY lab face (plan/07 WS10: one gateway API per face), so "the routes the gateway uses" IS every face invoke; `machine` is allowed at the faces and denied at the console (existing gate). Not a per-face list, because the gateway's own surface is the whole list. |
| A2 decision 3 — streaming methods | **adopted** | Not in the deny set; `authz.py` documents this as deliberate (advertised, not exercised). |
| Pre-existing failures "environment-dependent" | **agreed** | The same four fail at HEAD~2 in a clean baseline here too; Codex's 13 loopback errors did not reproduce (its environment lacks the extras). Listed as a separate triage item. |
