## Deploy runbook — run from the Salesforce work machine

This machine has no access to the lab's AWS account, so nothing here is
deployed. Every image below bakes `src/`, so each is a FULL rebuild, never
`--skip-build` (CLAUDE.md). Order does not matter between them; all read the
same secrets. Each script now fails fast if a shipped token is missing from
`.env` (A3) — that is the new guard working, not a broken script.

```sh
git checkout ws25-b1-security-seams
uv sync --all-extras && uv run pytest -q          # expect 571 passed, 4 pre-existing failed
aws sso login                                      # profile from AWS_PROFILE in .env
deploy/faces/deploy_faces.sh                       # A1 redaction at the 14 faces
deploy/bridge/deploy_bridge.sh                     # A1 + A3 bridge guard
deploy/console/deploy_console.sh                   # A1 + A2 DELETE gate + role copy
deploy/shim/build_zip.sh && deploy/shim/deploy_shim.sh        # A1 (shim records inbound A2A)
deploy/fanout/build_zip.sh && deploy/fanout/deploy_fanout.sh  # A1 + A3 lambda guard
```

Hosted smoke after deploy: a viewer JWT `DELETE /api/traces` → 403; a
`POST /invoke` through the faces with a body containing `"client_secret"` →
the recorded hop in `/api/traces` shows `[REDACTED]`; bridge and fan-out
`/healthz` green (they started, so their tokens were present).

Then the one-off scan (A1 tail):
```sh
grep -lE '"(client_secret|access_token|refresh_token|password|user_token)"\s*:\s*"[^\[]' traces/*.jsonl
```
and the same predicate over Aurora `trace_events.request_payload_raw`
(`scripts/pg_backfill.py` shows the connection shape). Scrub in place only if
something real is found; record the count either way in this file.
