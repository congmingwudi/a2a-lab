## Baseline before any edit (df1b23d + b2 proposal 038d9fb, this machine)

`uv sync --all-extras && uv run pytest -q`: **614 passed, 3 failed, 3 skipped,
6 deselected**. The 3 failures are exactly the b2 targets, all in
`tests/unit/test_fail_closed_auth.py`:

- `test_bridge_main_exits_before_serving_when_hosted_and_tokenless`
- `test_faces_main_refuses_hosted_tokenless_and_honours_opt_in`
- `test_console_main_refuses_hosted_tokenless_and_honours_opt_in`

Root cause (proven by moving `.env` aside → 20 passed): `main()` calls
`load_dotenv()`, which repopulates the token the `clean_env` fixture deleted, so
the guard finds a token and the sentinel `uvicorn.run` is reached. Note: the four
build-laptop "pre-existing" failures ws25-b1 documented (`test_console` harvest
x2, `test_oauth_token_endpoint`, `test_openai_agents_backend`) do **not**
reproduce on this machine and are untouched — a separate triage item, as b1 said.

## Change (test-only, `tests/unit/test_fail_closed_auth.py`)

| Test | Stub added | Why this target |
|---|---|---|
| bridge `main()` | `clean_env.setattr("dotenv.load_dotenv", …)` | bridge imports `load_dotenv` inside `main()` (`src/bridge/app.py:270`) → resolved from the `dotenv` module at call time |
| console `main()` | `clean_env.setattr("dotenv.load_dotenv", …)` | same call-time import (`src/console/app.py:4768`) |
| faces `main()` | `clean_env.setattr(faces_main, "load_dotenv", …)` | faces binds the name at module import (`src/faces/__main__.py:16`); the package symbol would not replace the bound reference |

Each stub sits alongside the existing `load_secret_env_and_log` stub, completing
the startup-side-effect isolation. `require_token` stays real — the guard is not
disabled, only `.env` is kept out.
